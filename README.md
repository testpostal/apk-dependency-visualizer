# Инструмент визуализации графа зависимостей пакетов Alpine Linux

## 1. Общее описание
CLI-утилита на языке Java для сбора, анализа и визуализации графа зависимостей пакетов Alpine Linux (формат `apk`). Загрузка индекса репозитория, распаковка архивов `.tar.gz`, разбор конфигурации YAML и построение графа транзитивных зависимостей реализованы средствами стандартной библиотеки Java без использования внешних менеджеров пакетов и сторонних библиотек.

## 2. Описание функций и настроек
При запуске приложение считывает конфигурационный файл `config.yaml`, валидирует параметры и строит полный граф зависимостей с учётом транзитивности с помощью рекурсивного алгоритма поиска в ширину (BFS). При обходе графа отслеживаются посещённые узлы, что позволяет корректно обрабатывать циклические и повторные зависимости без зацикливания.

Поддерживаются два источника данных:
* **Реальный репозиторий Alpine Linux (`repo_mode: false`)** — загрузка и разбор файла `APKINDEX.tar.gz` по указанному URL с разрешением виртуальных зависимостей (`p:`).
* **Тестовый репозиторий (`repo_mode: true`)** — чтение описания графа из локального текстового файла, где имена пакетов задаются заглавными латинскими буквами (формат `A: B C`).

Основные параметры в `config.yaml`:
* `package_name` — имя анализируемого пакета (например, `2bwm` или `A` в тестовом режиме).
* `repository_url` — URL-адрес репозитория Alpine Linux или путь к файлу тестового репозитория.
* `repo_mode` — режим работы с тестовым репозиторием (`true` — локальный файл, `false` — удалённый репозиторий).
* `package_version` — версия анализируемого пакета (например, `0.4-r0`).
* `output_image_path` — путь для сохранения итогового изображения графа в формате `.png`.
* `ascii_tree_output` — режим вывода зависимостей в формате ASCII-дерева (`true`/`false`).

## 3. Сборка и запуск тестов
Для компиляции, прогона тестов и запуска основного приложения используется скрипт `run.bat`:

```bash
run.bat
```

Скрипт последовательно выполняет:
1. Компиляцию исходного кода из `src/*.java` и тестов из `tests/*.java` в директорию `out/`.
2. Запуск автоматических тестов валидации параметров конфигурации и демонстрационных сценариев построения графа на тестовых репозиториях (`tests/repo_dag.txt`, `tests/repo_cycle.txt`, `tests/repo_isolated.txt`).
3. Запуск основного приложения с чтением файла `config.yaml`.

## 4. Примеры использования

### Пример 1: Анализ реального пакета Alpine Linux
Конфигурация `config.yaml`:
```yaml
package_name: 2bwm
repository_url: https://alpinelinux.org
repo_mode: false
package_version: 0.4-r0
output_image_path: graph.png
ascii_tree_output: false
```

Вывод в консоль:
```text
Граф зависимостей для пакета '2bwm':
  2bwm -> so:libc.musl-x86_64.so.1, xcb-util-wm, xcb-util-keysyms, so:libxcb-randr.so.0, xcb-util-xrm, so:libxcb.so.1
  so:libc.musl-x86_64.so.1 -> (нет зависимостей)
  xcb-util-wm -> so:libc.musl-x86_64.so.1, so:libxcb.so.1
  xcb-util-keysyms -> so:libc.musl-x86_64.so.1, so:libxcb.so.1
  so:libxcb-randr.so.0 -> (нет зависимостей)
  xcb-util-xrm -> so:libc.musl-x86_64.so.1, so:libxcb-util.so.1, so:libxcb.so.1
  so:libxcb.so.1 -> (нет зависимостей)
  so:libxcb-util.so.1 -> (нет зависимостей)
Обнаружены повторные/циклические переходы:
  * xcb-util-wm -> so:libc.musl-x86_64.so.1
  * xcb-util-wm -> so:libxcb.so.1
  * xcb-util-keysyms -> so:libc.musl-x86_64.so.1
  * xcb-util-keysyms -> so:libxcb.so.1
  * xcb-util-xrm -> so:libc.musl-x86_64.so.1
  * xcb-util-xrm -> so:libxcb.so.1
```

### Пример 2: Работа с тестовым репозиторием и циклическими зависимостями
Конфигурация `config.yaml`:
```yaml
package_name: A
repository_url: tests/repo_cycle.txt
repo_mode: true
package_version: 1.0
output_image_path: graph.png
ascii_tree_output: false
```

Вывод в консоль:
```text
Граф зависимостей для пакета 'A':
  A -> B
  B -> C, D
  C -> A
  D -> D
Обнаружены повторные/циклические переходы:
  * C -> A
  * D -> D
```
